# Product Requirements Document (PRD)

## Project: **Hylo‑Builders** (working title)

*Fork of Hylo.com re‑targeted as the community layer for builders.dev*

---

### 1  Purpose / Vision

Deliver a locally running fork of Hylo that is re‑branded, GitHub‑aware, and ships a **group companion agent plugin (Kortix Suna)** out‑of‑the‑box so early users can:

1. Create or join holonic groups for their coding projects.
2. Link those groups to one or more GitHub repos.
3. Ask Suna for insights, TODO scaffolds, or repo summaries inside each group.

This MVP keeps the existing Node/GraphQL stack intact; Elide is a future upgrade path.

---

### 2  Goals & Non‑Goals

|                | In‑Scope (Sprint 0‑1)                   | Out of Scope (later)                     |
| -------------- | --------------------------------------- | ---------------------------------------- |
| **Run fork**   | Local Docker + cloud dev env (Windsurf) | Full CI/CD pipeline                      |
| **Branding**   | builders.dev colors + logo swap         | Custom mobile apps                       |
| **Auth**       | GitHub OAuth + magic‑link email         | SSO, federation                          |
| **Suna agent** | Plug‑in architecture + default Suna bot | Multi‑agent orchestration, Elide runtime |
| **Repo link**  | One‑click connect repo → group          | Advanced metrics (vibestack)             |
| **UI**         | Minimal tweaks to surface Suna sidebar  | New design system                        |
| **Governance** | Keep Hylo roles (member/mod/admin)      | Co‑op tokenomics                         |

---

### 3  Personas & Key Use Cases

1. **Solo Builder (Dev)** – wants feedback on repo health & next features.
2. **Non‑Dev Founder** – creates a group, links Figma + GitHub, asks Suna for “technical roadmap”.
3. **Maintainer Squad** – migrates existing OSS tool into a holon, uses group chat + Suna to triage issues.

### 4  Functional Requirements

| FR‑ID | Description                                                                         | Priority |

| FR‑09 | Basic analytics page: stars, open issues, last release (via GitHub REST)            | P2       |

---

### 5  Non‑Functional Requirements

* **Local dev ≤ 1 command** (`make dev` or `docker compose up`).
* **Latency** for Suna reply ≤ 5 s (streamed).
* **Privacy**: store only public GitHub data + minimal OAuth tokens.
* **Extensibility**: plugin system must allow ≥ 2 more agents without code changes.

### 7  Risks & Mitigations

| Risk               | Impact       | Mitigation                     |
| ------------------ | ------------ | ------------------------------ |
| Suna API churn     | Agent fails  | Version‑pin & fallback message |
| GitHub rate limits | Delays stats | Cache & worker queue           |
| Plugin security    | RCE          | Sandbox via Daytona by default |
